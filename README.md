# on-Press-it-
Team 9 Project 

프로젝트 이름 : Press It !

하이퍼 캐주얼 리듬 게임 (모바일)

- 개발 기간: 26.03.04 ~ 26.04.15
- 팀 구성: 5명

## 목표
빠른 템포의 플레이와 직관적인 리듬 판정을 기반으로,
짧은 시간 안에 몰입할 수 있는 하이퍼 캐주얼 리듬 게임 제작

## 게임 플레이
- 리듬에 맞춰 입력하는 게임
- 판정: Perfect / Great / Good / Miss
- 스테이지 진행에 따라 난이도 증가
- 보스 스테이지에서 테마 및 연출 변화

- ## 입력 방식
- 터치 입력 기반
- 타이밍에 맞춰 화면 입력
- 탭, 홀드, 슬라이드 입력 방식

- UI 디자인 및 인터페이스 구성
- 게임 리소스 제작
- QA 및 테스트

## 프로젝트 상태
- 주요 기능 구현 완료
- 빌드 및 플레이 가능 상태
- 일부 구조 리팩토링 진행 예정

## 핵심 기능
- AudioSource 기반 타임라인 시스템 (CurrentTime)
- 판정 / 이벤트 / 스폰 시스템 분리 구조
- 연출과 로직 완전 분리 (연출 없이도 플레이 가능)
- UniTask 기반 비동기 초기화 및 씬 전환
- Firebase 기반 플레이어 데이터 저장/로드
- 스테이지 데이터 기반 구조 (확장 가능)
- 커스텀 에디터 툴을 통한 스테이지 시각화

## 데이터 구조
- 스테이지 데이터 기반으로 모든 이벤트 관리
- JSON을 통해 플레이어 데이터 저장
- Firebase를 통한 서버 동기화 지원

## 타임라인 기반 시스템
- AudioSource의 시간을 기준으로 CurrentTime 관리
- 모든 시스템이 동일한 시간 기준으로 동작

## 시스템 분리 구조
- JudgmentSystem → 판정 처리
- RhythmEventSystem → 이벤트 실행
- NoteSpawnSystem → 노트 생성

각 시스템이 독립적으로 동작하도록 설계

## 문제 해결 및 설계 개선 계획
### 1. CurrentTime 전역(static) 의존 문제
- 문제 : 모든 시스템이 static CurrentTime에 직접 의존하여, 테스트가 어렵고 시스템 간 결합도가 높음
- 원인 : 시간 흐름을 전역 상태로 공유하는 구조로 인해, 의존성 주입이 불가능한 구조
- 해결 : ICurrentTime 인터페이스를 도입하여 시간 제공자를 추상화하고, 각 시스템에 주입하는 방식으로 변경 예정
- 효과 : 단위 테스트 가능, 시스템 간 결합도 감소
### 2. 일부 매니저 책임 과다 문제
- 문제 : 특정 매니저가 여러 역할(로직 처리, 상태 관리, 흐름 제어 등)을 동시에 담당하여 유지보수 난이도 증가
- 원인 : 초기 구현 단계에서 기능 중심으로 빠르게 확장되며 책임 분리가 충분히 이루어지지 않음
- 해결 : 각 책임을 독립된 시스템 단위로 분리하고, 매니저는 흐름 제어 역할만 수행하도록 재구성 예정
- 효과 : SOLID 원칙 준수, 유지보수성 및 확장성 향상, 시스템 단위 테스트 가능
### 3. 초기화 순서 재정의
- 문제 : 일부 시스템 및 매니저의 초기화 순서가 명확하지 않아, 런타임에서 NullReference 등의 문제 발생 가능
- 원인 : 초기화 로직이 분산되어 있으며, 의존성 순서가 코드 레벨에서 보장되지 않음
- 해결 : 초기화 대상들을 인터페이스로 분리하고, 비동기 초기화 파이프라인을 구성하여 순서를 명시적으로 제어
- 효과 : 초기화 순서 명확화, 런타임 안정성 향상, 초기화 흐름 가독성 증가
### 4. 오브젝트 풀링
- 문제 : 리듬 게임 특성상 다수의 노트가 생성/파괴되며, 잦은 메모리 할당과 GC 발생 가능성 존재
- 원인 : 현재 구조에서 객체의 라이프사이클 및 상태 초기화가 명확하지 않아, 풀링 적용 시 안정성 문제 발생
- 해결 : 구조 리팩토링 이후, 다음과 같은 방식으로 오브젝트 풀링 도입 예정
- 효과 : GC 발생 감소, 성능 안정성 확보, 객체 재사용 기반의 효율적인 메모리 관리
