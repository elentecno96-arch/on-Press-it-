# on-Press-it-
Team 9 Project 

프로젝트 이름 : Press It !

하이퍼 캐주얼 리듬 게임 (모바일)

- 개발 기간: 26.03.04 ~ 26.04.15
- 팀 구성: 5명

## 목표
빠른 템포의 플레이와 직관적인 리듬 판정을 기반으로,
짧은 시간 안에 몰입할 수 있는 하이퍼 캐주얼 리듬 게임 제작

## 게임 플레이
- 리듬에 맞춰 입력하는 게임
- 판정: Perfect / Great / Good / Miss
- 스테이지 진행에 따라 난이도 증가
- 보스 스테이지에서 테마 및 연출 변화

- ## 입력 방식
- 터치 입력 기반
- 타이밍에 맞춰 화면 입력
- 탭, 홀드, 슬라이드 입력 방식

## 팀 구성
본 프로젝트는 5인 팀으로 진행되었으며,  
각 역할에 따라 다음과 같이 작업을 분담

- 코어 시스템 설계 및 구현
- 서브 시스템 개발 및 기능 보조
- UI 디자인 및 인터페이스 구성
- 게임 리소스 제작
- QA 및 테스트

## 프로젝트 상태
- 주요 기능 구현 완료
- 빌드 및 플레이 가능 상태
- 일부 구조 리팩토링 진행 예정

## 핵심 기능
- AudioSource 기반 타임라인 시스템 (CurrentTime)
- 판정 / 이벤트 / 스폰 시스템 분리 구조
- 연출과 로직 완전 분리 (연출 없이도 플레이 가능)
- UniTask 기반 비동기 초기화 및 씬 전환
- Firebase 기반 플레이어 데이터 저장/로드
- 스테이지 데이터 기반 구조 (확장 가능)
- 커스텀 에디터 툴을 통한 스테이지 시각화

## 데이터 구조
- 스테이지 데이터 기반으로 모든 이벤트 관리
- JSON을 통해 플레이어 데이터 저장
- Firebase를 통한 서버 동기화 지원

## 타임라인 기반 시스템
- AudioSource의 시간을 기준으로 CurrentTime 관리
- 모든 시스템이 동일한 시간 기준으로 동작

## 시스템 분리 구조
- JudgmentSystem → 판정 처리
- RhythmEventSystem → 이벤트 실행
- NoteSpawnSystem → 노트 생성

각 시스템이 독립적으로 동작하도록 설계

## 문제 해결 및 설계 개선 계획
### 1. CurrentTime 전역(static) 의존 문제
- 문제 : 모든 시스템이 static CurrentTime에 의존
- 해결 : ICurrentTime 인터페이스로 분리 예정
- 효과 : 테스트 가능, 시스템 독립성 확보
### 2. 일부 매니저 책임 과다 문제
- 문제 : 구현 목표로 인해 책임 과다문제로 유지보수 어려움
- 해결 : 각 책임을 일부 시스템과 분리
- 효과 : SOILD 원칙 적용, 강한 결합 문제 해결로 유지보수가 확보
### 3. 초기화 순서 재정의
- 문제 : 일부 몇 클래스의 초기화 순서가 명확하지않음
- 해결 : 인터페이스로 초기화할 매니저, 시스템을 나눠 놓고, 비동기로 초기화 처리
- 효과 : 런타임 중 널 예방, 가독성 증가
